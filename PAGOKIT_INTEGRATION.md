# PagoKit Integration

Generated by PagoKit on 2026-09-23.

## Configuración

- Proveedor: Wompi (Colombia) — API `v1`
- SDK: ninguno oficial; se usa `fetch` directo contra la API de Wompi (`lib/payments/wompi.ts`)
- Stack: Next.js App Router, desplegado en Cloudflare Workers (vinext)
- ORM: Drizzle (dialecto SQLite / Cloudflare D1)
- Modalidad de cobro: pago único (Wompi no ofrece suscripciones nativas)
- Frontend: Widget embebido de Wompi (`widget.js`)

Mr. Shaky Nutribar es un negocio de **recogida en tienda** (sin envíos), así que el checkout
tiene dos caminos y el cliente elige uno en el formulario "Planifica tu pedido":

1. **Efectivo al recoger** — no se cobra nada en línea; el pedido queda `pending_pickup`.
2. **Pago en línea con Wompi** — tarjeta, PSE, Nequi, Bancolombia, o vouchers en efectivo
   (Efecty/Baloto), a elección del cliente dentro del propio Widget de Wompi.

## Desviación del esquema estándar de PagoKit

El esquema genérico de 5 tablas de PagoKit (`payments`, `subscriptions`, `customers`,
`idempotency_keys`, `webhook_events_processed`) se adaptó al modelo real del sitio: en vez de una
tabla `payments` genérica se usa una tabla `orders` (pedido de recogida) que además guarda pago,
porque en este negocio pedido y pago son la misma entidad. No hay tabla `customers` (no hay
cuentas de usuario) ni `subscriptions` (no aplica). Se mantienen `pagokit_idempotency_keys` y
`pagokit_webhook_events_processed` con la convención estándar.

## Eventos de webhook manejados

- ✅ `transaction.updated` — único evento requerido por Wompi para pagos únicos
  (`required_events_minimum`). Cubre APPROVED, PENDING, DECLINED, VOIDED, ERROR.
- ⏳ Cualquier otro tipo de evento se registra con `console.log('[wompi.webhook] unhandled event', ...)`
  en `app/api/webhook/wompi/route.ts:78` — Wompi no emite otros eventos para este tipo de integración.

## Webhooks existentes detectados al instalar

- Ninguno. Se buscaron rutas `**/webhook*`, `**/api/webhook/**`, `**/notifications*`, `**/ipn*`,
  `**/events*` antes de generar y no había ninguna. El endpoint de Wompi quedó en
  `/api/webhook/wompi` por convención, dejando espacio para otros proveedores en el futuro.

## Próximos pasos

1. Completa `.env.local` con tus llaves de prueba de Wompi (dashboard sandbox → Configuración →
   Llaves API / Eventos / Integridad). Usa `.env.example` como plantilla.
2. Genera y aplica la migración: `npm run db:generate` (ya generada en este repo) — al desplegar,
   la plataforma aplica el SQL contra el D1 real (ver el mensaje de error de `db/index.ts` si el
   binding no está listo).
3. Corre `/pagokit:test` para enviar un evento firmado de prueba al webhook.
4. Cuando el flujo de sandbox pase, revisa `PAGOKIT_PRODUCTION_CHECKLIST.md` antes de poner
   llaves reales.

## Aviso legal — regulación regional

El negocio opera en Colombia y cobra en COP. Aplica la **Ley 1581 de 2012 (Habeas Data)** para
el tratamiento de datos personales: solo se recolecta nombre y celular del cliente (lo mínimo
necesario para identificarlo en la sucursal — Rule 11), sin dirección, documento de identidad ni
fecha de nacimiento. Wompi no es Merchant of Record, así que la facturación/DIAN sigue siendo
responsabilidad de Mr. Shaky Nutribar (factura electrónica si aplica según tus ingresos).
